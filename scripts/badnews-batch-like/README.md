# Bad.news 批量点赞工具 1.0.1

1.0.1 修复排行榜识别：不再将 `login-required` 事件样式当作账号未登录的证据；悬停才显示的点赞按钮按可见 `.relatedlist` 条目识别。面板自动更新异步加载结果，并说明无可处理项的原因。真正出现登录入口时仍停止，不尝试绕过登录。

独立 Tampermonkey 脚本，通过网站原生点赞按钮操作当前账号；不是 Raindrop 收藏工具。点赞可能影响公开评分，请自行确认站点的点赞/收藏含义并遵守站点规则。

## 使用

安装 `badnews-batch-like.user.js`，登录网站后刷新页面。点击右下角“批量点赞”，选择“正文作品”“右侧排行榜”或两者，再点“开始点赞”。默认收起，不会自动执行。油猴菜单也可打开面板。

- 仅处理当前页面已经加载且可见布局中的按钮，不自动翻页或抓取视频。
- 按 `data-tid` 去重，同一作品的多个按钮只点一次；已点赞的作品跳过，不点击踩按钮。
- 默认每项确认后间隔 2 秒，最低 1.5 秒，串行操作。
- 通过 `.midcol.likes` 或实心点赞图标判断网页反馈，再等待状态稳定。仅确认 UI，不声称校验服务器持久化。
- 登录提示、未知状态、按钮消失、页面切换、10 秒无反馈或反馈回退时停止。已尝试项在本次页面生命周期内不重复点击，避免取消点赞。
- “停止”阻止后续点击，不能撤回已经发出的操作；若最后一项状态不明，请手动刷新核对。
- 不读密码、Cookie，不调用猜测接口，不上传页面信息；只有用户点击开始后才触发网站原生按钮。

## 验证范围

根据当前搜索结果页及右侧排行榜的只读 DOM 检查适配 `.midcol[data-tid]`、`fa-thumbs-o-up` 和 `.side` / `top-content-*`。检查时页面未登录，没有替用户点赞。已点赞状态与批处理保护经过本地模拟测试；登录后的真实站点反馈尚待用户验证。若页面改版导致状态无法识别，脚本会停止而不是盲目连续点击。

测试：设置包含 Playwright 的 `NODE_PATH` 后运行 `node scripts/badnews-batch-like/badnews-batch-like.test.cjs`。
