# Bad.news 批量点赞工具 1.1.0

## 连续处理正文多页

选择“正文作品”，填写“正文连续页数”（1–1000，包含当前页），再点击开始。例如处理第 3–8 页：先自行打开第 3 页，再填 6。默认 1 页；排行榜及正文＋排行榜仍只处理当前页。

当前页完成后，跟随页面已有的可识别“下一页”链接导航，再继续运行；不猜测页码地址。目前识别 `rel=next`、常见分页 next 控件及明确的中英文下一页文字，并要求同源、同列表路径（允许 `/page/N` 或 `page`/`p` 查询参数）。不支持的分页结构会停止，需按实际页面适配。到末页、下一页不明确、出现循环、登录失效或点赞反馈异常时停止。

任务在当前标签页的 sessionStorage 中暂存页间交接信息（目标 URL、计数、作品 ID，不含凭据），到达指定下一页后仅消费一次，2 分钟过期。正常页面处理期间不保存自动续跑状态：手动刷新/导航会中断，不会无限恢复。不要同时手动切页或复制正在交接的标签页。每次翻页前、下一页启动前各留 1.5 秒停止窗口；跨页重复作品跳过，面板显示当前页数及累计计数。

跨页功能仅通过本地模拟测试，尚未在实际登录网页验证分页兼容性；自动提交的是用户指定范围内的原生点赞。

1.0.3 将默认间隔改为 1000 毫秒（1 秒），最小值仍为 250 毫秒。

1.0.2 将可设置的最小间隔调整为 250 毫秒（0.25 秒），默认仍为 2000 毫秒。该间隔在上一项网页状态确认并稳定 1200 毫秒后计算，并不保证每 0.25 秒产生一次点击。

1.0.1 修复排行榜识别：不再将 `login-required` 事件样式当作账号未登录的证据；悬停才显示的点赞按钮按可见 `.relatedlist` 条目识别。面板自动更新异步加载结果，并说明无可处理项的原因。真正出现登录入口时仍停止，不尝试绕过登录。

独立 Tampermonkey 脚本，通过网站原生点赞按钮操作当前账号；不是 Raindrop 收藏工具。点赞可能影响公开评分，请自行确认站点的点赞/收藏含义并遵守站点规则。

## 使用

安装 `badnews-batch-like.user.js`，登录网站后刷新页面。点击右下角“批量点赞”，选择“正文作品”“右侧排行榜”或两者，再点“开始点赞”。默认收起，不会自动执行。油猴菜单也可打开面板。

- 每页只处理已经加载且可见布局中的按钮；仅正文指定多页时自动翻页，不抓取视频。
- 按 `data-tid` 去重，同一作品的多个按钮只点一次；已点赞的作品跳过，不点击踩按钮。
- 默认每项确认后间隔 1 秒，最低 0.25 秒，串行操作。另保留 1200 毫秒的状态稳定检查。
- 通过 `.midcol.likes` 或实心点赞图标判断网页反馈，再等待状态稳定。仅确认 UI，不声称校验服务器持久化。
- 登录提示、未知状态、按钮消失、页面切换、10 秒无反馈或反馈回退时停止。已尝试项在本次页面生命周期内不重复点击，避免取消点赞。
- “停止”阻止后续点击，不能撤回已经发出的操作；若最后一项状态不明，请手动刷新核对。
- 不读密码、Cookie，不调用猜测接口，不上传页面信息；仅用户点击开始后及该次指定范围的跨页续跑中触发网站原生按钮。

## 验证范围

根据当前搜索结果页及右侧排行榜的只读 DOM 检查适配 `.midcol[data-tid]`、`fa-thumbs-o-up` 和 `.side` / `top-content-*`。检查时页面未登录，没有替用户点赞。已点赞状态与批处理保护经过本地模拟测试；登录后的真实站点反馈尚待用户验证。若页面改版导致状态无法识别，脚本会停止而不是盲目连续点击。

测试：设置包含 Playwright 的 `NODE_PATH` 后运行 `node scripts/badnews-batch-like/badnews-batch-like.test.cjs`。
